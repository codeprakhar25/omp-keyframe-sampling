subs OFF, batch_size=1, LongCLIP scorer, ONE environment (AWS g6e.xlarge / L40S).

## 1. R11 — blind / text-only floor

blind_600 (zero frames) = .4369 (n=412).

The benchmark is 43.7% answerable from question + options alone. Every selector
number must be read against this floor, not against zero. For scale:
blind -> uniform = +10.9pt; uniform -> OMP = +9.95pt. Choosing WHICH eight frames
is worth almost as much as having frames at all.

## 3. AKS PORTING BUG — our AKS was top-k

`harness/replay_selectors.py::aks_indices` ends with a branch NOT present in the
official ncTimTang/AKS `frame_select.py`:

    if len(uniq) < k:
        order = list(np.argsort(-score))   # global top-k
        ...pad...

Mechanism. Official AKS defaults max_num_frames=64, all_depth=5, so
int(64/2^5) = 2 frames per leaf. At k=8 with the same depth, int(8/2^5) = 0:
EVERY leaf contributes zero frames, the recursion returns nothing, and the pad
branch fills the entire selection from global top-k. The official code has no
pad and would return zero frames -- i.e. the configuration is out of range, and
our padding converted "out of range" into a plausible-looking wrong answer.
Condition: k < 2^all_depth (so k=8 and k=16 affected; k=32 is FINE, f_num=1).

Evidence, three independent ways:
  (a) recomputed aks_indices(all_depth=5) == argsort(-score)[:k], 412/412;
  (b) stored picks_aks vs stored picks_topk compared as FRAME INDICES:
      406/412 identical (98.54%); the 6 exceptions differ by one ADJACENT frame,
      a rounding round-trip (gen_aks_picks rounds seconds to 0.1,
      export_picks_lmmseval writes unrounded floats);
  (c) McNemar k8_aks vs k8_topk: b=1, c=0, p=1.
Scope check across every benchmark and bin (frame overlap within 1s):
  LVB15 .898 | LVB60 .992 | LVB600 .997 | LVB3600 .998 |
  VMMshort .999 | VMMmed .999 | VMMlong 1.000 | LVBench .998 | LVB600 k32 .315
=> degenerate everywhere at k=8 (5,586 items, 3 benchmarks); k=32 unaffected.

Published-number corroboration: in Table 1, AKS and top-k are the CLOSEST pair on
all three benchmarks (LVB .6021 vs .6028 = 0.07pt; VMM .5785 vs .5704 = 0.81pt;
LVBench .4280 vs .4319 = 0.39pt), while other rows spread 4-6pt.

### Correction and its result

Fix = all_depth=2, which preserves the official k/2^depth = 2 frames-per-leaf
ratio. Overlap with top-k drops .997 -> .475 (LVB600); regenerated for all 8
benchmark/bin sets.

  AKS(fixed) stem  = .5922   vs top-k .6068  (-1.46, p=.556)
                             vs aks(bug) .6092 (-1.70, p=.483)
  AKS(fixed) fused = .6311

Correctly configured AKS is a WEAK selector at k=8: it falls from 3rd to 5th on
LVB-600s, above only uniform. The correction does not favour us.

## 4. Selector audit — only AKS is affected

Pairwise frame overlap (within 1s) across LVB600/LVB3600/VMMlong/LVBench:
only aks|topk exceeds .95. Next highest is dppmm|omp at .57-.65 (related
query-aware greedy methods, 25/31 discordant answers -- distinct).
Code audit: `aks_indices` holds the ONLY padding branch in the selectors module.
  - LDDR-select: has a "backfill if volume collapsed" branch that NEVER FIRES
    (0/412 videos, 0/3296 frames) -- dead code, row is sound.
  - FOCUS*: fills from `leftovers` WITHIN its own selected clips, never from
    global top-k -- degrades inside its own method. Already disclosed as a
    schedule replay.

CAVEAT: this audit proves no two arms are secretly the same method. It does NOT
prove each is faithful to its paper. AKS was caught only because it collapsed
onto another arm; a wrong-but-distinct implementation would pass silently.
